# 이권욱

**IT 프로젝트 및 품질관리 매니저**

자동차 인포테인먼트 개발 지원에서 PMO를 맡아 프로젝트 일정과 요구사항 변경을 관리하고, 품질 위험에 대응해 왔습니다.  
교육 연계 팀 프로젝트에서는 하이브리드 클라우드의 전체 아키텍처를 설계하고, 서버 설정을 자동화하는 코드와 Python 배포 프로그램을 직접 개발했습니다.  
일정과 변경을 조율한 경험을 바탕으로, 설계한 내용이 실제 구성과 시험 결과에 어떻게 반영됐는지 함께 검토합니다.  

자세한 담당 업무와 시험 조건은 [기술 포트폴리오](https://forested-walk-e30.notion.site/FDS-3f970bc8a619817c852fdb9e5fef8d47)에 정리했습니다.  

## 프로젝트 관리와 품질 업무

- **프로젝트 일정과 변경 관리:** 변경이 발생하면 관계 부서와 대응 일정 및 우선순위를 조율하고, 후속 조치가 이행됐는지 확인했습니다.
- **Automotive SPICE에 따른 업무:** 프로젝트 관리, 시스템 요구사항 분석, 변경 요청 관리와 품질 보증을 수행했습니다. 요구사항과 산출물의 연결 관계를 검토하고, 품질팀과 함께 변경 영향을 분석했습니다.
- **직접 수행한 테스트와 QA 리드 경험:** 보험 ERP와 업무 시스템의 통합 테스트 및 인수 테스트를 수행하고, 관련 가이드를 작성했습니다. 스마트폰 검증에서는 테스트 계획을 세우고 결함과 산출물을 관리했습니다.

## 321Team의 FDS 하이브리드 클라우드 프로젝트

2026년 8월부터 10월까지 참여한 교육 연계 팀 프로젝트입니다.  
FDS는 거래의 위험 징후를 규칙에 따라 판정하고 결과를 기록하는 서비스입니다.  
교육장의 Kubernetes 환경을 AWS의 관리형 OpenShift인 ROSA HCP로 확장하는 아키텍처를 설계했습니다.  
앱은 클라우드에 배치하고 PostgreSQL과 Harbor는 온프레미스에 유지하도록 구성과 통신 경로를 정했습니다.  

### 맡은 일

전체 아키텍처와 배포 경로를 설계하면서, 앱이 사용하는 통신과 운영자가 관리하는 경로를 구분했습니다.  
작업을 시작하는 데 필요한 조건과 승인 범위를 정리하고, 시험 결과와 남은 과제를 바탕으로 후속 일정을 조율했습니다.  

Ansible로 Kubernetes 여섯 노드의 공통 설정과 사전 점검을 코드화했습니다.  
Python 배포 프로그램에는 실행 전 승인 조건 검사, 요청 전 기록과 상태 확인을 구현했습니다.  
응답을 받지 못하거나 실제 상태가 예상과 다르면 추가 변경을 멈추고, 미완료 작업을 자동으로 반복하지 않도록 했습니다.  
정해진 소스 버전에서 구성 파일을 수집하고 해시값을 대조하는 도구도 만들었습니다.  

Trivy 검사에서 심각도가 높거나 치명적인 취약점이 남아 있거나 검사 자체가 실패하면, 이미지 등록과 배포로 진행하지 않도록 절차를 구현했습니다.  
기반 이미지의 교체는 팀이 함께 결정했으며, 패키지 버전 고정과 자동 검사 조건 정리는 지원 역할을 맡았습니다.  

AWS 자원 코드 작성과 적용은 팀원이 담당했습니다.  
저는 Terraform의 변경 계획과 적용 후 설정을 비교해 설계 조건에 맞게 반영됐는지 검토했습니다.  

### 시험으로 확인한 범위

| 사례 | 확인한 결과 | 시험 범위 |
| --- | --- | --- |
| 서버 설정 반복 적용 | 이미 올바르게 설정된 여섯 노드의 SSH 구성을 각각 두 번 적용해도 추가 변경 없이 유지됐습니다. | 실제 노드에 적용하고 다시 적용한 기록 |
| 테스트 실패 후 중단 | 정상 앱 테스트 16건 뒤에 검증용 1건을 실패시키자 빌드와 검사가 진행되지 않았습니다. 시험 전후 두 시점에서 배포 설정 2개와 파드 6개가 참조하는 이미지가 같았습니다. | 이미지 등록과 배포 작업을 제외한 별도 실제 실패 시험 |
| 배포 프로그램의 중단 처리 | 응답 유실이나 상태 불일치가 발생하면 추가 변경을 멈추고, 미완료 작업을 자동으로 반복하지 않는 동작을 확인했습니다. | 모의시험 |

위 사례는 기술 포트폴리오에서 2026년 10월 22일까지 대조한 시험 기록을 기준으로 정리했습니다.  
배포 프로그램의 모의시험을 실제 클라우드 자동 배포 실적으로 확대하지 않았으며, 각 시험의 환경과 시점은 포트폴리오에 표시했습니다.  

온프레미스에서는 무결성과 추적성, 재현성을 중요하게 봤습니다.  
클라우드로 옮기는 설계에서는 공통 구성과 환경별 설정을 나눠 이식성도 고려했습니다.  
사용한 원본과 실행 기록을 연결해, 변경 결과를 다시 확인할 근거를 남겼습니다.
